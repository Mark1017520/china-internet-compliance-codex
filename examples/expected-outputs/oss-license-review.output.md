# Reference Output: 开源许可证审查

## 初步结论

建议结论：存在高风险组件，完成许可证核验和替代方案前不建议对外交付 Docker 镜像或私有化部署包。

MIT、PostgreSQL License 通常较宽松，但 AGPL、SSPL 或 Elastic License 在 SaaS、镜像分发和私有化部署下可能触发更重义务或商业限制。

## 主要风险

| 组件 | 等级 | 说明 |
|---|---|---|
| `agpl-example-lib` | P0/P1 | AGPL 可能触发网络服务场景源码提供义务，需核验使用方式 |
| `elasticsearch` | P1 | SSPL/Elastic License 版本差异较大，需确认精确版本和授权 |
| Docker 镜像交付 | P1 | 分发场景可能触发 notice、许可证文本、源码或清单义务 |
| 私有化部署 | P1 | 客户合同需披露第三方软件和限制条件 |

## 必补材料

- 精确组件名、版本号和许可证文本
- 是否修改源码、链接方式和运行方式
- Docker 镜像和部署包内容清单
- 客户合同中的第三方软件、源码、授权和赔偿条款
- 是否有商业授权或替代组件方案

## 整改建议

1. 生成 SBOM，并按组件核验许可证和版本。
2. 暂停 AGPL/SSPL 高风险组件进入对外交付镜像。
3. 评估替换为宽松许可证组件、商业授权或架构隔离。
4. 为镜像和私有化包准备第三方软件清单、notice 和许可证文本。
5. 与客户合同保持一致，避免承诺无第三方限制或无限制再分发。

## 上线 Gate

SaaS 场景可在完成高风险组件核验后灰度；Docker 镜像和私有化部署需完成替换、商业授权或法律复核后再交付。
