# Reference Output: 监管或公安调证响应

## 初步结论

建议结论：补齐文书真实性核验和内部审批后，在请求范围内最小化提供材料。

该请求涉及手机号、登录 IP、设备信息、订单信息和站内消息，属于高敏感响应流程。不得擅自扩大提供范围，也不得删除、篡改或隐瞒证据。

## 处理流程

1. 法务核验协查函主体、盖章、联系人、联系方式、案由、请求范围和送达方式。
2. 数据/安全团队确认数据所在系统、可查询范围、留存期限和查询权限。
3. 业务负责人确认账号、订单和站内消息的业务关联。
4. 双人复核导出结果，留存查询日志、审批记录和交付记录。
5. 对外回复仅覆盖文书要求的账号、字段和时间范围。

## 风险点

| 风险 | 等级 | 说明 |
|---|---|---|
| 文书真实性或范围不清 | P0/P1 | 需补充核验后再提供 |
| 超范围提供个人信息 | P1 | 只能按请求目的和范围最小化提供 |
| 查询和导出无留痕 | P1 | 需保留审批、查询、导出和交付记录 |
| 站内消息内容敏感 | P1 | 需确认请求依据和必要性 |

## 必补材料

- 原始协查函和送达记录
- 内部审批单和法务意见
- 数据字段清单、时间范围和账号匹配结果
- 查询人、复核人、导出时间和交付方式
- 如范围不清，需向请求机关补充确认的问题清单

## 对外回复要点

- 说明已按来函请求和公司流程核验处理。
- 列明提供材料清单、账号、时间范围和字段范围。
- 对不存在、超出留存期限或无法确认的数据作事实说明。
- 保留交付签收或安全传输记录。

## 上线 Gate

该事项不是产品上线 gate，而是监管/司法响应 gate。未完成文书核验和内部审批前，不应导出或交付数据。

## 依据状态

- 待核验依据：公安调证、个人信息提供、日志留存和证据响应相关规则需核验最新版官方文本和公司制度。
