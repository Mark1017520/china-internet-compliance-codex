# Reference Output: AI 客服助手上线审查

## 初步结论

建议结论：整改后可上线。

该功能同时触发 AI/AIGC、个人信息处理、供应商数据处理、交易售后信息和日志留存合规维度。若第三方模型 API、用户告知、AIGC 标识、人工兜底和数据处理协议未补齐，不建议直接全量上线。

## 主要风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 第三方模型处理用户咨询和订单信息 | P1 | 需确认是否出境、是否用于训练、是否有 DPA |
| AI 回复误导消费者 | P1 | 售后、退款、物流承诺需可追溯并可转人工 |
| AIGC 标识不足 | P1 | 用户应能识别自动生成或自动回复内容 |
| 知识库或会话中含敏感信息 | P2 | 需做输入过滤、脱敏、权限控制和日志留存 |

## 必补材料

- 模型供应商数据处理条款和部署区域说明
- 是否使用用户会话训练模型
- 隐私政策、个人信息处理规则和第三方共享清单
- AI 回复标识、转人工机制、错误回复纠错流程
- 日志留存、查询权限和安全审计方案

## 整改建议

1. 产品：在会话入口和回复内容中增加 AI 标识，并提供一键转人工。
2. 研发：对订单号、手机号、地址、售后描述做最小化传输和敏感信息过滤。
3. 法务/隐私：补充模型供应商 DPA、跨境判断和隐私政策更新。
4. 客服运营：建立错误回复升级、申诉和人工复核流程。
5. 安全：限制知识库和会话日志访问权限，保留审计记录。

## 上线 Gate

整改后灰度上线。灰度期间应监控误答率、转人工率、投诉率、敏感信息拦截命中率和供应商接口日志。

## 依据状态

- 待核验依据：AI/AIGC、个人信息保护、数据出境和供应商处理相关规则需核验最新版官方文本。
- 事实假设：默认第三方模型 API 可能接触用户咨询内容和部分订单信息。
