# Reference Output: App SDK 权限审查

## 初步结论

建议结论：补充材料并整改后可上线。

当前方案中剪贴板、设备标识符、相册、通知和客服会话内容均需逐项说明必要性。SDK 清单、隐私政策、权限弹窗和实际初始化行为必须一致。

## 主要风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 用户同意前 SDK 提前初始化 | P1 | 需核查代码位置和启动链路 |
| 剪贴板读取必要性不足 | P1 | 容易触发高敏权限争议，应默认关闭或场景触发 |
| SDK 清单与实际采集不一致 | P1 | 需按 SDK 官方字段和实际抓包核验 |
| 相册权限范围过宽 | P2 | 应改为用户主动上传时触发 |

## 必补材料

- SDK 官方文档、版本号和采集字段
- Android/iOS 权限申请文案和触发时机
- SDK 初始化代码位置
- 隐私政策、第三方共享清单和个人信息清单
- 与 SDK 服务商的数据处理、安全和退出条款

## 整改建议

1. 研发：调整 SDK 初始化为同意后或具体业务场景触发。
2. 产品：删除非必要权限，剪贴板和相册权限改为用户动作触发。
3. 隐私合规：更新 SDK 清单、隐私政策和第三方共享说明。
4. 安全：对 SDK 实际采集字段做抓包或日志核验。

## 上线 Gate

暂不建议直接全量上线。完成权限最小化、同意链路、SDK 清单和实际采集核验后，可灰度上线。

## 依据状态

- 待核验依据：App 个人信息保护、SDK 共享、权限调用和终端权限相关规则需核验最新版官方文本。
- 事实假设：默认 SDK 服务商可接收设备信息和部分日志。
