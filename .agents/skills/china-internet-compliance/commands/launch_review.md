# /china-compliance:launch_review

## 1. 命令契约

- 命令名称：`/china-compliance:launch_review`
- 任务类型：产品上线 Gate 审查
- 适用场景：新功能、PRD、灰度、A/B 测试、重大版本、回滚方案
- 目标输出：上线 gate、跨场景风险、阻断项、整改项、灰度监控和回滚条件

## 2. 必需输入

| 字段 | 缺失时处理 |
|---|---|
| PRD/功能说明、用户路径、页面截图或流程图 | 缺失则不能给最终 gate |
| 上线地区、用户对象、灰度范围、回滚方案 | 缺失时列为上线前必须补齐 |
| 数据字段、权限、SDK/API、模型、供应商 | 技术功能默认必需 |
| 协议、隐私政策、活动规则、客服/申诉路径 | 涉及用户权益时必需 |
| 历史同类功能和审批结论 | 可选，但有助于校准风险 |

## 3. 执行流程

1. 抽取功能事实和上线计划。
2. 识别跨场景风险：数据、AI、内容、广告、交易、支付、游戏、IP、供应商、监管。
3. 路由专项 Skill，合并专项结论。
4. 形成阻断项、上线前整改项、灰度监控项、上线后观察项。
5. 明确 owner、关闭标准、证据材料和回滚触发条件。
6. 输出单页上线 gate 结论。

## 4. 缺失材料处理

- 无 PRD/流程：输出待补材料和初步风险，不给上线结论。
- 无回滚方案：P1，上线前必须补。
- 涉及付费、未成年人、敏感数据、AI 公共服务但无专项材料：P1/P0。

## 5. 输出格式

```markdown
# 产品上线合规 Gate
## 1. 功能和上线计划
## 2. 场景路由
## 3. Gate 结论
## 4. 阻断项/上线前整改项/灰度监控项
## 5. 责任方与关闭标准
## 6. 回滚和监控指标
## 7. 可复制评审结论
```

## 6. 质量门槛

- 必须给出 gate：阻断、整改后上线、灰度上线、可上线并监控。
- 每个 P0/P1 必须有 owner 和关闭标准。
- 必须列明灰度/回滚条件。
