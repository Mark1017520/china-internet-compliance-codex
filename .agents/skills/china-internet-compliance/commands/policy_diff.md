# /china-compliance:policy_diff

## 1. 命令契约

- 命令名称：`/china-compliance:policy_diff`
- 任务类型：法规、监管规则、平台规则或内部制度变更影响评估
- 适用场景：新规发布、征求意见稿转正式稿、平台规则更新、公司制度修订、监管口径变化
- 目标输出：规则变化点、受影响场景、系统/协议/流程/合同改造项、优先级、责任方、过渡期安排
- 不做事项：不在未核验来源时给最终法律定论；不把征求意见稿当作已生效规则

## 2. 必需输入

| 类别 | 必需字段 | 缺失时处理 |
|---|---|---|
| 新旧规则 | 新文本、旧文本或变更摘要、发布机关、发布日期、生效日期 | 无法 diff 时先输出资料缺口 |
| 来源状态 | 官方链接、内部制度版本号、平台公告链接、核验日期 | 标记为待核验依据 |
| 影响范围 | 涉及产品线、地区、用户对象、数据/AI/广告/交易等场景 | 用场景 taxonomy 反推可能影响 |
| 当前实践 | 现有系统逻辑、协议文本、流程 SOP、合同模板、运营规则 | 输出“无法判断差距”的风险 |
| 时间要求 | 生效日、过渡期、监管检查或上线 deadline | 无 deadline 时按高变化规则建议排期 |

## 3. 执行流程

1. 识别规则类型：法律、行政法规、部门规章、国家标准、监管通知、平台规则、内部制度。
2. 核验来源状态：官方正式稿、征求意见稿、解读稿、二手转载、内部草案分别标注。
3. 做条款级 diff：新增义务、删除义务、口径收紧、口径放宽、程序变化、处罚变化。
4. 映射业务影响：产品、数据、AI、内容、广告、交易、支付、游戏、供应商、监管响应。
5. 输出差距清单：当前做法是否满足新规则，缺系统、缺协议、缺审批还是缺证据。
6. 形成改造计划：P0/P1/P2/P3、owner、截止时间、验证方式、上线/存量整改策略。
7. 更新来源索引建议：需要写入 `SOURCE_INDEX.yaml` 的字段和核验状态。

## 4. 缺失材料处理

- 只有新规没有旧规：按“新增规则影响评估”输出，不做逐条差异结论。
- 只有新闻稿或解读稿：标记待核验，不得写成正式义务。
- 不清楚公司当前实践：输出调研清单和系统/协议抽样范围。
- 不清楚生效时间：列为 P1 待确认，避免遗漏整改窗口。

## 5. 输出格式

```markdown
# 政策/规则 Diff 影响评估

## 1. 来源核验
| 文件 | 版本/日期 | 来源 | 状态 |
|---|---|---|---|

## 2. 变化点矩阵
| 条款/主题 | 旧规则 | 新规则 | 变化类型 | 影响等级 |
|---|---|---|---|---|

## 3. 受影响业务场景
| 场景 | 影响说明 | 涉及系统/协议/流程 | 责任方 |
|---|---|---|---|

## 4. 差距与整改计划
| 差距 | 整改动作 | 优先级 | 截止时间 | 验证证据 |
|---|---|---|---|---|

## 5. SOURCE_INDEX 更新建议

## 6. 可复制管理层摘要
```

## 6. 质量门槛

- 必须区分正式稿、征求意见稿、解读稿和二手来源。
- 必须输出“变化点—受影响业务—整改动作—证据”的闭环。
- 必须给出新规生效日或将其列为阻断性缺口。
- 必须说明是否需要更新 `SOURCE_INDEX.yaml`、templates、commands 或 company profile。
