# /china-compliance:compliance_register

## 1. 命令契约

- 命令名称：`/china-compliance:compliance_register`
- 任务类型：合规风险台账与整改闭环
- 适用场景：评审会后整理、多产品整改跟踪、上线 gate 管理、审计留痕、监管问询准备
- 目标输出：风险编号、事实依据、责任方、整改动作、关闭标准、证据材料、状态、复核人
- 不做事项：不重新作完整法律分析；以既有评审结论和补充事实为基础建立跟踪台账

## 2. 必需输入

| 类别 | 必需字段 | 缺失时处理 |
|---|---|---|
| 项目信息 | 项目名、产品线、版本、上线时间、负责人 | 缺失则生成临时编号 |
| 风险来源 | 评审结论、会议纪要、PRD 批注、监管要求、测试报告 | 标记来源缺口 |
| 风险项 | 风险描述、触发事实、影响场景、风险等级 | 无等级时按 P1 待分级 |
| 整改闭环 | 整改动作、owner、截止日、关闭标准、验证证据 | 无关闭标准时不得标为 closed |
| 复核机制 | 复核人、复核日期、是否允许上线、灰度/回滚条件 | 缺失则标记为待审批 |

## 3. 执行流程

1. 合并重复风险：同一触发事实、同一整改动作、同一 owner 的风险合并并保留来源。
2. 分配编号：按 `项目-场景-等级-序号` 生成稳定 ID。
3. 标准化等级：P0 阻断、P1 上线前整改、P2 灰度监控、P3 记录观察。
4. 明确关闭标准：每个风险必须有可验证证据，不接受“已沟通”“后续关注”作为关闭。
5. 输出上线 gate 汇总：哪些风险阻断，哪些允许灰度，哪些可上线后监控。
6. 输出审计留痕：来源、责任方、证据、复核人、版本和状态变更记录。

## 4. 缺失材料处理

- 缺少风险等级：暂定 P1，并要求法务/隐私/安全复核。
- 缺少 owner：不得进入执行状态，列为待分配。
- 缺少关闭标准：不得标记为完成。
- 缺少验证证据：状态只能是 `待验证`，不能是 `已关闭`。
- 评审结论互相冲突：输出冲突清单并升级复核。

## 5. 输出格式

```markdown
# 合规风险整改台账

## 1. 台账摘要
| 项目 | 版本 | 总风险 | P0 | P1 | P2 | P3 | 上线 Gate |
|---|---|---:|---:|---:|---:|---:|---|

## 2. 风险台账
| ID | 风险 | 触发事实 | 等级 | 整改动作 | Owner | 截止日 | 关闭标准 | 证据 | 状态 |
|---|---|---|---|---|---|---|---|---|---|

## 3. 上线 Gate
- 阻断项：
- 上线前必须关闭项：
- 可灰度监控项：

## 4. 状态变更记录
| 日期 | 风险 ID | 变更 | 复核人 | 备注 |
|---|---|---|---|---|
```

## 6. 质量门槛

- 每个风险必须有 ID、等级、owner、关闭标准和证据字段。
- 不得把没有证据的整改项标为已关闭。
- 必须输出上线 gate 汇总。
- 必须保留风险来源，便于审计追溯。
