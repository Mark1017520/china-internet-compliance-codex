# /china-compliance:regulatory_response

## 1. 命令契约

- 命令名称：`/china-compliance:regulatory_response`
- 任务类型：监管问询、公安调证、行政检查、诉讼/仲裁证据响应
- 适用场景：协查函、调证函、监管问询函、行政检查通知、平台投诉转办、诉讼证据保全
- 目标输出：文书核验、权限审批、范围控制、材料目录、脱敏方案、交付记录、风险升级建议
- 不做事项：不协助规避监管、隐匿证据、删除日志、伪造材料或绕过公司审批

## 2. 必需输入

| 类别 | 必需字段 | 缺失时处理 |
|---|---|---|
| 请求来源 | 机关/法院/仲裁/平台/律师函主体、联系人、送达方式 | 未核验前不得导出材料 |
| 文书信息 | 文书类型、案号/函号、盖章/签名、请求依据、截止时间 | 标记为 P0/P1 待核验 |
| 请求范围 | 账号/订单/时间段/字段/材料类型/格式要求 | 范围不清则先回函确认 |
| 数据与材料 | 登录日志、订单、通信内容、身份信息、源代码、风控标签、合同 | 分级判断是否可提供 |
| 内部审批 | 法务、隐私、安全、业务、管理层审批链路 | 缺审批不得交付 |
| 交付方案 | 脱敏、加密、签收、传输渠道、留痕、原始证据保全 | 缺失则输出交付风险 |

## 3. 执行流程

1. 核验请求主体和文书形式：主体权限、印章、案由、联系人、送达渠道。
2. 建立请求范围表：账号、时间、字段、系统、格式、是否包含第三方或无关用户。
3. 做材料分级：可直接提供、需脱敏提供、需补充文书、原则不提供、需管理层升级。
4. 做最小必要筛选：删除超范围账号、超范围时间、内部标签、源代码、无关商业秘密。
5. 建立导出审批：查询人、导出人、复核人、审批人、导出时间、文件 hash 或清单。
6. 形成对外回复：材料目录、字段说明、未提供原因、无法提供原因、保留事项。
7. 保留证据链：原始文书、审批记录、查询记录、导出记录、交付签收和后续沟通。

## 4. 缺失材料处理

- 文书真实性不明：P0，暂停导出和交付。
- 请求范围过宽：先要求明确范围，或只按最小必要提供。
- 涉及通信内容、敏感个人信息、未成年人、商业秘密、源代码：升级法务/安全/管理层。
- 要求删除或修改日志：拒绝执行并升级。
- 截止时间极短：先做保全和范围确认，不牺牲审批留痕。

```markdown
| 编号 | 材料 | 来源系统 | 脱敏/加密 | 复核人 | 状态 |
|---|---|---|---|---|---|

## 4. 超范围/不提供材料
| 材料 | 不提供或限制原因 | 替代说明 |
|---|---|---|

## 5. 内部审批与交付留痕

## 6. 对外回复要点
```

## 6. 质量门槛

- 必须先核验文书和请求范围，再讨论材料交付。
- 必须明确哪些材料可提供、需脱敏、需补文书、原则不提供。
- 必须输出审批和交付留痕要求。
- 必须显式禁止删除、篡改、隐藏或伪造证据。
