# /china-compliance:quick_triage

## 1. 命令契约

- 命令名称：`/china-compliance:quick_triage`
- 任务类型：不完整需求的合规分诊
- 适用场景：会议口头需求、PRD 草稿、只知道功能概念、需要判断应走哪个专项审查
- 目标输出：主场景、交叉场景、P0/P1 快速信号、最小补材料清单、下一步 command/Skill

## 2. 必需输入

| 字段 | 缺失时处理 |
|---|---|
| 功能一句话说明 | 无法分诊时先要求用户补一句话 |
| 用户对象和上线地区 | 缺失时按中国大陆公众用户保守判断 |
| 是否涉及数据、AI、UGC、广告、交易、支付、游戏、未成年人、开源、供应商 | 逐项未知，不得默认否 |
| 当前阶段：想法/PRD/开发/灰度/上线/事故 | 缺失时标记为待确认 |

## 3. 执行流程

1. 用最少事实完成初步场景分类。
2. 扫描 P0/P1 信号：监管/公安、未成年人、敏感个人信息、出境、金融、医疗、游戏充值、AIGC 公共服务、源代码交付。
3. 输出下一步路由：单一 command 或组合 command。
4. 输出最小补材料，不超过 10 项，按优先级排序。
5. 给出临时 gate：可继续调研、需专项审查、暂停上线或升级。

## 4. 缺失材料处理

- 信息少于三项：只输出分诊问题，不给风险结论。
- 出现 P0 信号但材料不足：直接建议暂停上线并升级。
- 多场景交叉：列出主审 command 和协审 command。

## 5. 输出格式

```markdown
# 快速分诊
## 1. 已知事实
## 2. 主场景与交叉场景
## 3. P0/P1 快速信号
## 4. 推荐下一步
| 优先级 | Command/Skill | 原因 |
|---|---|---|
## 5. 最小补材料清单
## 6. 临时 Gate
```

## 6. 质量门槛

- 必须给出下一步 command/Skill。
- 必须说明哪些事实不足以支持最终结论。
- 不得输出“低风险/可上线”作为最终结论。
