# /china-compliance:cold_start_interview

## 1. 命令契约

- 命令名称：`/china-compliance:cold_start_interview`
- 任务类型：公司化落地访谈与 profile 生成
- 适用场景：企业首次接入本 Skill 包、建立公司风险偏好、审批矩阵、数据分类、升级规则和输出口径
- 目标输出：`COMPLIANCE_PROFILE.md` 草案、审批流程、风险校准表、数据分类表、法务升级矩阵、资料接入清单
- 不做事项：不对单个产品功能给最终上线结论；只建立公司通用审查口径

## 2. 必需输入

| 类别 | 必需问题 | 缺失时处理 |
|---|---|---|
| 公司画像 | 业务类型、主要产品、服务对象、上线地区、是否面向公众用户 | 标记为 profile 阻断项 |
| 高风险场景 | 是否涉及 AI、个人信息、未成年人、内容、广告、交易、支付、游戏、开源、跨境 | 逐项询问，不得默认否 |
| 组织责任 | 法务、隐私、安全、产品、研发、运营、客服、商业化负责人 | 输出待指定责任方 |
| 审批机制 | P0/P1/P2/P3 分级、谁有上线否决权、灰度和回滚要求 | 使用默认建议并标记待确认 |
| 数据治理 | 数据分类、敏感个人信息、重要数据、日志留存、权限审批 | 输出最小可用数据分类草案 |
| 资料入口 | PRD、SDK 清单、SBOM、合同库、数据地图、模型台账、法规库 | 输出 connectors 接入优先级 |

## 3. 执行流程

1. 先做公司业务地图：产品线、用户对象、地区、交易/内容/AI/数据触点。
2. 建立风险分级口径：定义 P0 阻断、P1 上线前整改、P2 灰度监控、P3 记录观察。
3. 建立审批矩阵：按风险等级和场景分配法务、隐私、安全、业务 owner。
4. 建立数据分类：普通个人信息、敏感个人信息、重要数据、日志、商业秘密、监管材料。
5. 建立专项路由：把公司高频场景映射到 11 个 specialist Skills 和 15 个 commands。
6. 建立证据清单：每类审查必须提供哪些材料，哪些缺失会阻断上线。
7. 建立输出口径：上线 gate、整改项、关闭标准、复核记录、可复制结论。
8. 输出 profile 草案和落地待办，不得把未确认口径写成公司最终制度。

## 4. 缺失材料处理

- 公司业务范围不清：先输出访谈问题清单，不生成最终 profile。
- 审批权责不清：给出 RACI 草案并标记需管理层确认。
- 数据分类缺失：使用保守默认分类，但标记“待隐私/安全确认”。
- 法规来源未接入：标记所有外部依据为“待核验依据”。
- 未明确是否跨境：按“可能跨境”列入 P1 待确认。

## 5. 输出格式

```markdown
# 公司化合规 Profile 草案

## 1. 公司业务画像
| 项目 | 内容 | 状态 |
|---|---|---|

## 2. 高频合规场景与路由
| 场景 | 推荐 Skill/Command | 默认风险等级 | 责任方 |
|---|---|---|---|

## 3. 风险分级与上线 Gate
| 等级 | 定义 | 是否可上线 | 审批人 | 关闭标准 |
|---|---|---|---|---|

## 4. 数据分类与处理要求
| 数据类型 | 示例 | 默认控制 | 证据材料 |
|---|---|---|---|

## 5. 审批矩阵
| 场景 | 产品 | 法务 | 隐私 | 安全 | 管理层 |
|---|---|---|---|---|---|

## 6. 资料接入清单
| 资料源 | 用途 | 优先级 | 接入方式 |
|---|---|---|---|

## 7. 待管理层确认事项
```

## 6. 质量门槛

- 必须覆盖业务画像、风险分级、审批矩阵、数据分类、资料接入和输出口径。
- 必须至少列出 10 个公司化访谈问题。
- 必须明确哪些是默认建议，哪些需要公司确认。
- 必须输出可落地的 profile 文件结构，而不是泛泛建议。
