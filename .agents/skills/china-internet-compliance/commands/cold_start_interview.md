# /china-compliance:cold_start_interview

## 1. 命令契约

- 命令名称：`/china-compliance:cold_start_interview`
- 任务类型：公司化配置访谈
- 适用场景：首次接入、公司风险偏好、审批流程、业务画像配置
- 目标输出：生成profile、风险校准、升级矩阵、审批流程和数据分类
- 默认法域：中国大陆互联网合规；涉及境外、跨境、海外供应商或海外上线时，必须标注跨境复核。

## 2. 必需输入

执行前先抽取或要求补充以下字段：

| 字段 | 是否必须 | 缺失时处理 |
|---|---|---|
| 项目/功能名称 | 是 | 用用户描述临时命名，但标注“名称待确认” |
| 业务目标与功能说明 | 是 | 无法判断主场景时先执行 quick_triage |
| 上线地区与用户对象 | 是 | 缺失时按“中国大陆公众用户”高风险假设处理 |
| 业务流程/用户路径 | 是 | 输出流程缺口并要求补图/截图/PRD |
| 数据字段/权限/SDK/API/模型/供应商 | 条件必须 | 只要涉及技术处理，即列为上线前确认项 |
| 是否涉及AI、内容、广告、交易、游戏、支付、未成年人、开源/IP、跨境 | 是 | 逐项询问；不得默认“不涉及” |
| 协议/隐私政策/活动规则/合同/资质/截图/日志 | 条件必须 | 对 P0/P1 事项列入证据缺口 |

## 3. 可选输入

- 历史同类项目结论；
- 公司 profile、风险偏好、审批流程；
- 外部律师意见、监管沟通口径；
- 代码仓库、SCA/SBOM、SDK清单、数据地图、模型台账。

## 4. 执行流程

1. 使用 `INPUT_FACT_SCHEMA.md` 抽取事实，区分“已确认事实 / 假设 / 缺失材料”。
2. 使用 `INDUSTRY_SCENARIO_TAXONOMY.md` 判断主场景与交叉场景。
3. 读取对应专项 Skill 的 `SKILL.md` 与 `PLAYBOOK.md`。
4. 对本命令的 P0/P1 信号逐项排查；材料缺失不得自动降级。
5. 使用 `CITATION_GUARDRAILS.md` 标注依据状态：已核验依据、待核验依据、内部规则/风险偏好、事实假设、人工复核。
6. 使用 `DUTY_TO_EVIDENCE_MATRIX.md` 反推证据材料。
7. 输出风险等级、待确认问题、整改建议、责任方、关闭标准和 Gate。
8. 最后执行“质量门槛”自检。

## 5. 推荐调用路径

读取 `profiles/COLD_START_INTERVIEW.md`，生成公司化 profile、风险校准、升级矩阵和审批流程。

## 6. 缺失材料处理

- 缺少业务流程：先输出分诊，不得给最终上线结论。
- 缺少数据字段/SDK/API/模型清单：涉及技术处理时默认 P1 待确认。
- 缺少合同/授权/资质：涉及供应商、IP、广告、支付、特殊行业时默认 P1 待确认。
- 缺少法规定版依据：标注“待核验依据”，不得写成确定法律意见。

## 8. 质量门槛

- 必须识别主场景和至少一个交叉场景；确实无交叉场景时说明理由。
- 必须输出至少 3 个待确认问题；信息充分时可写“无新增待确认”，但要说明材料来源。
- 对 P0/P1 结论必须写明：触发事实、依据状态、证据缺口、关闭标准。
- 输出不得以“建议咨询律师”代替具体审查；可提示人工复核，但仍需给出初步判断。
