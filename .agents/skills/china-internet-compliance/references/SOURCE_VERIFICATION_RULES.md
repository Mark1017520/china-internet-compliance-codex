# Source Verification Rules — 来源核验规则

## 1. 来源优先级

| 优先级 | 来源类型 | 说明 |
|---|---|---|
| S1 | 用户提供的项目文件、合同、PRD、SDK清单、数据字段、系统日志 | 事实依据优先级最高，但需注意是否完整、是否最新 |
| S2 | 公司内部制度、审批流程、合规标准、历史案例、风险偏好 profile | 决定公司内部 gate 和升级要求 |
| S3 | 官方法规、部门规章、国家标准、监管规则、监管公告 | 支撑法律义务判断 |
| S4 | 法院裁判、行政处罚、行业协会规范、监管问答 | 支撑风险趋势和解释判断 |
| S5 | 行业经验、外部律师观点、公开文章、模型静态知识 | 仅作辅助，不得单独支撑重大结论 |

## 2. 需要强制核验最新版的主题

- 数据出境安全评估、标准合同、认证、豁免或便利化规则。
- 算法备案、生成式AI备案、安全评估、深度合成、AIGC标识。
- App专项治理、SDK权限、个人信息清单、权限弹窗。
- 互联网广告、直播带货、金融广告、医疗/药品/教育广告。
- 网络游戏审批、防沉迷、未成年人充值、虚拟资产。
- 金融、支付、钱包、分账、信贷/保险/理财导流。
- 公安调证、监管问询、行政检查、证据提供范围。

## 3. 核验动作

当工具或连接器可用时，优先执行：

1. 检索官方法律法规库或公司法规模块；
2. 打开项目文件、PRD、合同、内部制度；
3. 对比法规版本、生效日期、适用范围；
4. 将结论标记为“已核验依据”。

当无法核验时：

- 不停止分析；
- 将依据标记为“待核验依据”；
- 给出需要核验的具体文件或来源；
- 避免绝对化结论。
