# 开源许可证与第三方代码审查矩阵

> 使用说明：本矩阵用于初筛，不替代对具体许可证文本、项目双许可政策、商业附加条款、依赖链和实际使用方式的审查。

## 1. 先问使用方式

1. 仅开发工具使用，还是运行时依赖？
2. 源码复制、修改、Fork、Patch，还是包管理器依赖？
3. 静态链接、动态链接、进程内调用、命令行调用、独立服务、API调用？
4. 是否对外分发：源码、二进制、SDK、App、Docker镜像、插件、私有化部署包？
5. 是否作为网络服务向外部用户提供？
6. 是否与自研代码形成衍生作品或强耦合？
7. 是否保留版权声明、许可证文本、NOTICE、修改说明？

## 2. 常见许可证初筛

| 许可证 | 初步风险 | 常见义务/关注点 |
|---|---|---|
| MIT / BSD / ISC | 低 | 保留版权声明和许可证文本；注意第三方专利/商标不当然授权 |
| Apache-2.0 | 低-中 | 保留NOTICE；专利授权与终止条款；修改说明；商标不当然授权 |
| MPL-2.0 | 中 | 文件级 copyleft；修改 MPL 文件通常需开放相应文件源码 |
| LGPL | 中 | 动态链接通常可控；修改 LGPL 库需开放修改；静态链接/嵌入需重点评估 |
| GPL | 高 | 分发衍生作品通常触发源码开放义务；进程内集成、静态链接高风险 |
| AGPL | 高 | 修改版通过网络交互提供也可能触发源码提供义务；SaaS场景重点审查 |
| SSPL | 高 | 对作为服务提供的场景要求极强；可能要求开放服务管理相关代码，商业风险高 |
| BUSL / Elastic / Commons Clause | 中-高 | 需看商业使用、生产使用、托管服务、竞争服务、转售限制 |
| CC BY / CC BY-SA | 中 | 适合文本/图片/数据等内容；署名、相同方式共享、改编标识；不等同软件许可证 |
| Public Domain / CC0 | 低-中 | 仍需确认来源真实性、人格权、商标、隐私、数据权利 |

## 3. 高风险信号

- AGPL/SSPL/GPL 组件进入核心后端、SDK、客户端、插件、私有化部署包。
- Fork/修改开源项目但未保留许可证、NOTICE、修改说明。
- 复制 StackOverflow/GitHub gist/博客代码但无法确认许可证。
- 使用竞品开源代码、主题、模板、文档、字段名、测试数据，造成实质性相似。
- 开源仓库包含内部域名、密钥、token、账号、客户信息、日志、商业秘密。
- 使用素材、字体、图标、音乐、图片但只取得个人/非商业/不可嵌入/不可分发授权。

## 4. 降低风险路径

- 替换为宽松许可证组件。
- 将强 copyleft 组件隔离为独立服务，并确认是否仍触发网络服务条款。
- 避免修改原项目；如必须修改，准备源码提供、NOTICE、修改说明。
- 对外分发前做 SCA/SBOM 扫描和 LICENSE/NOTICE 包。
- 删除内部敏感信息，做秘密扫描。
- 对素材/字体/图片保留授权链和使用范围证明。


## V1.0.0增强说明

- 对许可证名称的初筛必须结合 `OPEN_SOURCE_DECISION_TREES.md` 中的使用方式决策树。
- 输出结论时不得只说“某许可证风险高/低”，必须同时说明：是否修改、是否分发、是否网络服务提供、集成方式、源码义务、NOTICE/LICENSE义务。
- 对 AGPL、SSPL、GPL、BUSL、Elastic、Commons Clause，应默认进入专项复核；除非事实明确显示仅作内部非生产工具且不修改、不分发、不网络提供。
