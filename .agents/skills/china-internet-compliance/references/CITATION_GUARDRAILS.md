# Citation Guardrails — 引用与依据校验规则

## 1. 适用范围

凡输出以下结论，应标注依据状态：

- P0 阻断或 P1 高风险结论。
- “需要备案 / 安全评估 / 许可 / 单独同意 / PIA / 数据出境机制 / AIGC标识 / 算法备案”等明确义务判断。
- “不得上线 / 暂不建议上线 / 不建议对外提供材料 / 存在行政处罚或侵权索赔风险”等重大判断。
- 对公安、监管、诉讼、仲裁、证据、日志、用户数据提供范围作出的判断。

## 2. 依据状态标签

| 标签 | 定义 | 示例 |
|---|---|---|
| 已核验依据 | 已从用户文件、内部制度、法规库、合同、PRD或明确材料中获取 | 用户提供的隐私政策、SDK清单、合同条款、法规库条文 |
| 待核验依据 | 静态规则库或模型知识提示的义务，需核对最新版官方文本 | 最新监管口径、备案要求、专项治理要求 |
| 内部规则/风险偏好 | 来自公司 profile、历史口径、管理层决策、内部制度 | 公司规定所有第三方SDK上线前必须安全评估 |
| 事实假设 | 基于现有事实作出的条件性假设 | 假设该功能面向中国大陆C端用户 |
| 律师复核 | 需要外部律师或专项团队确认 | 跨境法、金融许可、刑事风险、重大诉讼 |

## 3. 输出格式

建议对重大结论使用如下表格：

| 结论 | 依据/规则 | 来源状态 | 需补充证据 | 复核要求 |
|---|---|---|---|---|
| 暂不建议上线 | 可能涉及敏感个人信息处理和单独同意缺失 | 待核验依据 | 数据字段清单、授权页面、隐私政策 | 隐私合规复核 |

## 4. 禁止事项

- 不得编造条文编号、案例名称、监管批复或官方解释。
- 不得把“行业经验”写成“法律强制要求”。
- 不得在没有事实材料时给出“已合规”结论。
- 不得把未核验的静态规则表述为已确认的最新版法律要求。

## 5. 高风险引用要求

P0/P1 结论至少应包含：

1. 事实触发点；
2. 对应义务或风险规则；
3. 依据状态；
4. 待补充证据；
5. 人工复核角色。
