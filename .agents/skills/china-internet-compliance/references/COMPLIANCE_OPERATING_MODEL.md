# Compliance Operating Model — 企业合规运行模型

## 1. 三层运行模型

1. **通用规则层**：法规、监管规则、国家标准、行业规范、公司基础制度。
2. **场景规则层**：产品、数据、AI、内容、广告、交易、游戏、支付、开源、供应商、监管响应等场景规则。
3. **公司 Profile 层**：公司风险偏好、审批矩阵、产品线差异、上线 gate、历史案例和例外流程。

## 2. 审查对象分层

| 层级 | 示例 | 审查重点 |
|---|---|---|
| 产品功能 | 新页面、新流程、新能力 | 用户权益、合规提示、上线 gate |
| 技术方案 | SDK、API、算法、模型、日志、权限 | 数据、安全、开源、可控性 |
| 运营活动 | 抽奖、促销、直播、会员、内容活动 | 广告、价格、内容、消费者权益 |
| 商业合作 | 供应商、渠道、平台、达人、商家 | 合同、数据、责任边界、资质 |
| 响应事项 | 监管问询、公安调证、诉讼证据 | 范围、留痕、审批、口径一致 |

## 3. Gate 设计

- Gate 0：事实材料齐备性。
- Gate 1：是否触发强监管或强许可。
- Gate 2：数据/安全/AI/内容/IP专项是否通过。
- Gate 3：协议、隐私政策、规则、公示、用户授权是否完成。
- Gate 4：灰度、回滚、日志、投诉、应急机制是否可用。
- Gate 5：上线后监测责任方是否明确。

## 4. 例外机制

如果业务要求带风险上线，应输出：

- 例外原因；
- 未解决风险；
- 临时控制措施；
- 有效期；
- 审批人；
- 到期复核机制。
