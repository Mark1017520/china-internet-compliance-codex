# 法规更新与不确定性处理机制

> 版本：V1.0.1
> 最近核验日期：2026-06-02  
> 目标：防止 Codex 依据过期静态规则给出错误法律判断。

## 1. 必须核对最新版的事项

遇到以下问题时，输出中必须提示“需核对最新版官方规则/监管口径”，必要时不得给最终放行结论：

1. 数据出境安全评估、标准合同、保护认证、自由贸易试验区负面清单。
2. 算法备案、深度合成备案、生成式AI服务备案、安全评估。
3. 人工智能生成合成内容标识要求。
4. App权限、SDK、弹窗、预装软件、个人信息清单监管通报。
5. 未成年人网络保护、网络游戏防沉迷、直播打赏限制。
6. 网络交易平台规则、直播电商、平台经济监管。
7. 支付、清算、金融导流、征信、保险、贷款、理财、证券基金等强监管边界。
8. 医疗、教育、药品、保健食品、医疗器械、金融等特殊广告。
9. 网络出版、视听节目、新闻信息、直播、网络表演等内容资质。
10. 开源项目许可证变更、双许可、商业附加条款。

## 2. 推荐官方核验来源

- 全国人大/国家法律法规数据库：法律、行政法规。
- 中国政府网、司法部：国务院令、部门规章、政策解读。
- 国家互联网信息办公室/中国网信网：数据、App、算法、AIGC、内容治理、未成年人网络保护。
- 国家市场监督管理总局：广告、网络交易、价格、反不正当竞争、消费者权益。
- 国家新闻出版署、文化和旅游部、广电总局：游戏、出版、视听、直播、网络表演。
- 中国人民银行、国家金融监督管理总局、证监会：支付、金融导流、金融广告、反洗钱、征信等。
- 工信部：App、通信、短信营销、网络安全、工业和信息化领域规则。
- 许可证官方文本和项目仓库：开源许可证、双许可、商业限制。

## 3. 输出中的不确定性标签

| 标签 | 使用场景 | 示例表达 |
|---|---|---|
| 明确依据 | 法条或规章规则明确 | “依据个人信息保护法第55条，该场景原则上应做个人信息保护影响评估。” |
| 条件性判断 | 需要事实确认后才能定性 | “若该推荐流面向公众且具有舆论属性，需进一步判断算法备案。” |
| 监管趋势 | 监管文件/执法趋势支持但无单一法条直接覆盖 | “从App治理口径看，剪贴板读取需与功能直接相关并避免频繁读取。” |
| 公司风险偏好 | 法律未绝对禁止但不符合审慎合规策略 | “建议作为P1处理，避免在未成年人场景中设置充值抽奖。” |
| 需外部律师/主管机关确认 | 高风险、跨境、许可或重大争议 | “是否构成网络出版/网络视听服务需结合功能细节由外部律师或主管部门确认。” |

## 4. 版本维护建议

- 每季度更新一次 `REGULATORY_MAP.md`、`ARTICLE_LEVEL_RULES.md`、`VERTICAL_INDUSTRY_PLAYBOOKS.md`。
- 每次重大监管文件发布后更新对应规则。
- 对高频误判案例，新增到 `golden_examples/`。
- 对真实业务复盘案例，脱敏后沉淀为测试用例或优秀输出样例。
- 保留 `CHANGELOG.md`，记录规则来源、修改内容、影响场景。

## 5. 禁止输出方式

不得输出：

- “完全无风险”。
- “一定不需要备案/许可/评估”，除非事实和依据充分。
- “只要用户同意即可处理所有数据”。
- “API调用就不会有开源/数据/供应商风险”。
- “AI生成内容没有版权/IP风险”。
- “公安/监管要求什么就全部提供”。
