# 开源许可证使用方式决策树

> 使用说明：本文件补充 `OPEN_SOURCE_LICENSE_MATRIX.md`，用于按“使用方式”而非只按“许可证名称”判断开源义务。输出时应同时说明许可证风险和使用方式风险。

## 1. 第一问：是否对外分发？

### 1.1 不对外分发，仅内部使用

- 宽松许可证：一般保留许可文本即可。
- GPL/LGPL/MPL：通常不触发对外源码提供义务，但仍需遵守内部留痕、修改记录、许可保留。
- AGPL：若修改后通过网络向外部用户提供交互服务，即使不分发，也需要重点评估网络服务条款。
- SSPL：即使不传统分发，作为服务提供也可能带来非常高的开放服务相关代码风险。

### 1.2 对外分发源码、二进制、SDK、App、Docker镜像、插件、私有化包

- 必须做 SCA/SBOM。
- 必须随包提供 LICENSE/NOTICE。
- 强 copyleft 组件必须判断是否形成衍生作品、链接方式、修改范围、源码提供范围。
- 私有化部署包和 Docker 镜像属于高风险分发场景。

## 2. 第二问：是否修改了开源项目？

| 情形 | 风险判断 | 处理动作 |
|---|---|---|
| 未修改，仅包管理器依赖 | 看链接/调用/分发方式 | 保留许可证、NOTICE、版本清单 |
| 修改源码但不分发、不网络提供 | 内部留痕，AGPL/SSPL仍需看服务 | 修改记录、补丁隔离 |
| 修改源码并分发 | 高风险 | 按许可证开放修改部分或对应作品源码 |
| Fork后作为SaaS服务提供 | AGPL/SSPL高风险 | 法务专项评估，准备源码提供或商业授权 |

## 3. 第三问：集成方式是什么？

| 集成方式 | 典型风险 |
|---|---|
| 复制源码进自研仓库 | 容易形成衍生/混合，许可证污染风险高 |
| 静态链接 | GPL/LGPL风险升高，需评估源码提供和可替换性 |
| 动态链接 | LGPL相对可控，但仍需允许替换/调试和开放库修改 |
| 进程内调用/插件机制 | 需看耦合程度和许可证解释，GPL/AGPL谨慎 |
| 命令行调用/独立进程 | 风险低于链接，但分发和修改仍需评估 |
| 独立服务/API调用 | 一般降低GPL风险，但AGPL/SSPL仍需专项判断 |
| 前端打包进客户端 | 属于分发，高风险许可证应避免 |
| Docker镜像整体交付 | 属于分发，需要完整许可证清单和源码义务判断 |

## 4. 常见许可证细化规则

### MIT / BSD / ISC
- **风险**：低。
- **义务**：保留版权声明和许可证文本。
- **注意**：不当然授予商标权；来源真实性仍需核验。

### Apache-2.0
- **风险**：低-中。
- **义务**：保留许可证、NOTICE、修改说明；关注专利授权和专利报复终止条款。
- **注意**：商标不当然授权。

### MPL-2.0
- **风险**：中。
- **触发重点**：修改 MPL 覆盖文件并分发时，通常需要开放该文件源码。
- **整改**：保持文件级隔离；避免把自研代码写入 MPL 文件。

### LGPL
- **风险**：中。
- **动态链接**：通常可控，但要保留许可证、允许用户替换库、开放对 LGPL 库的修改。
- **静态链接/嵌入**：风险升高，需提供可重新链接机制或替代方案。

### GPL
- **风险**：高。
- **触发重点**：分发包含 GPL 代码的衍生作品通常要求开放相应源码。
- **高风险方式**：静态链接、复制源码、客户端分发、私有化包。
- **降低风险**：替换组件、独立进程隔离、仅内部工具使用、商业授权。

### AGPL
- **风险**：高。
- **触发重点**：修改版通过网络与用户交互，也可能触发向网络用户提供源码的义务。
- **高风险方式**：Fork/修改后作为后端服务、SaaS功能、私有化部署。
- **降低风险**：不修改、替换组件、商业授权、独立服务仍需谨慎评估。

### SSPL
- **风险**：很高。
- **触发重点**：作为服务提供可能要求开放服务管理、部署、监控等相关源代码。
- **处理原则**：原则上不作为核心生产服务组件引入；如必须使用，优先选择官方商业许可或替代组件。

### BUSL / Elastic License / Commons Clause
- **风险**：中-高。
- **触发重点**：商业使用、生产使用、托管服务、竞争性服务、转售、SaaS 提供常有额外限制。
- **处理原则**：不可按“开源许可证”简单放行；必须逐条核查许可证文本和项目双许可政策。

### CC BY / CC BY-SA / CC BY-NC / CC0
- **适用对象**：文本、图片、数据、文档、素材，不宜默认用于软件代码。
- **风险点**：署名、改编说明、相同方式共享、非商业限制、第三方权利、肖像权/商标权/隐私权。

## 5. 输出判断模板

```markdown
## 开源许可证判断
- 组件/素材名称：
- 来源链接/仓库：
- 许可证：
- 使用方式：内部工具 / 运行时依赖 / 源码复制 / 修改Fork / API调用 / Docker镜像 / SDK / App / 私有化包
- 是否修改：是/否/未知
- 是否对外分发：是/否/未知
- 是否网络服务提供：是/否/未知
- 初步风险等级：P0/P1/P2/P3
- 触发义务：LICENSE / NOTICE / 修改说明 / 源码提供 / 商业授权 / 替换
- 待确认问题：
- 建议处理：
```

## 6. 强制阻断建议

出现以下情况时，原则上不得直接上线：

1. 无法确认许可证的第三方代码进入生产系统。
2. GPL/AGPL/SSPL组件进入对外交付包但无许可证义务评估。
3. AGPL/SSPL项目被 Fork/修改并作为网络服务提供但无源码开放或商业授权方案。
4. 开源仓库包含内部密钥、token、账号、客户数据或商业秘密。
5. 使用 CC BY-NC、个人授权素材、试用字体、竞品素材用于商业广告或产品界面。
