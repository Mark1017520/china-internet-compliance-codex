# Golden Example — Health AI Advice Review

## 1. 输入事实摘要

App 计划上线“AI 健康助手”，用户输入症状、年龄、性别、用药史和体检报告后，模型生成健康建议和用药提醒。产品文案写“智能诊断”“推荐治疗方案”。团队未提供医疗资质、医生审核、风险分级、免责声明、数据敏感性评估和模型供应商合同。

## 2. 结论前置

- 风险等级：P0/P1
- 上线建议：不得以“诊断、治疗方案、用药决策”形式上线；如改为健康科普和就医提醒，需完成医疗边界、敏感个人信息 PIA、人工兜底和供应商 DPA 后再评估
- 核心理由：症状、体检和用药信息属于高度敏感信息，AI 输出可能影响用户生命健康。无资质情况下提供诊疗或用药建议存在重大监管和民事责任风险。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 输入数据 | 症状、用药史、体检报告 | 高敏感 |
| 输出 | 健康建议、用药提醒 | 高风险 |
| 文案 | 智能诊断、治疗方案 | 阻断 |
| 医疗资质 | 未提供 | 缺失 |
| 人工审核 | 未提供 | 缺失 |
| 模型供应商 | 未提供合同 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 无资质诊疗风险 | P0 | 使用“诊断/治疗方案”表述 | 删除诊疗承诺，明确非医疗诊断 |
| 生命健康损害风险 | P0/P1 | AI 给出用药建议 | 高风险问题引导就医，不输出用药决策 |
| 敏感个人信息处理不足 | P1 | 体检和健康数据 | 完成 PIA、单独同意、最小化和删除机制 |
| 模型供应商责任不清 | P1 | 第三方处理健康数据 | DPA 禁止训练、明确安全和删除 |
| 免责声明不足 | P1 | 用户可能依赖输出 | 页面显著提示并提供人工/医疗机构入口 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 删除“智能诊断”“治疗方案”“用药推荐”等表述和能力 | 产品/法务 | 上线前阻断项 |
| 将功能限定为健康科普、风险提示和就医建议 | 产品/医学顾问/法务 | 上线前 |
| 完成敏感个人信息 PIA、单独同意和数据最小化 | 隐私/产品 | 上线前 |
| 建立高危症状拦截、急症提示和人工/医疗机构转介 | 产品/安全 | 上线前 |
| 签署模型供应商 DPA，禁止使用健康数据训练 | 法务/采购 | 上线前 |

## 6. 上线 Gate

当前诊断和治疗方案版本应阻断上线。只有在功能边界调整为非诊疗健康科普，并完成敏感个人信息和模型供应商审查后，才可进入 P1 复核。

## 7. 依据状态

- 待核验依据：医疗广告/互联网诊疗、个人信息保护、敏感个人信息、生成式 AI 和消费者权益规则需核验最新版官方文本。
- 事实假设：平台自身未持有开展互联网诊疗所需资质。

## 8. 可复制评审结论

【结论】AI 健康助手当前方案不具备上线条件。涉及“诊断、治疗方案、用药提醒”的部分应 P0 阻断；如调整为健康科普和就医提醒，也需完成敏感个人信息 PIA、单独同意、高危场景转介、模型供应商 DPA 和显著免责声明后再评估。
