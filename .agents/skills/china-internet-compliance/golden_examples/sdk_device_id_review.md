# Golden Example — SDK Device ID Review

## 1. 输入事实摘要

App 拟接入第三方统计 SDK。SDK 文档显示会采集 OAID、Android ID、设备型号、IP 地址、应用安装列表和崩溃日志。研发计划在 App 启动时初始化 SDK；隐私政策仅写“用于统计分析”，未列明 SDK 名称、字段和共享目的。

## 2. 结论前置

- 风险等级：P1 高风险
- 上线建议：完成 SDK 清单、同意链路、字段最小化和启动时机整改后再上线
- 核心理由：设备标识符和安装列表属于高关注数据，启动即初始化和隐私政策披露不足均存在合规风险

## 3. 事实矩阵

| 项目 | 内容 | 状态 |
|---|---|---|
| SDK 用途 | 统计分析和崩溃分析 | 已知 |
| 采集字段 | OAID、Android ID、IP、设备型号、安装列表、崩溃日志 | 待实测 |
| 初始化时机 | App 启动 | 高风险 |
| 用户告知 | 仅笼统描述 | 不充分 |
| 服务商合同 | 未提供 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 同意前初始化风险 | P1 | App 启动即初始化 | 改为用户同意后初始化或关闭采集 |
| 字段最小化不足 | P1 | 采集安装列表等高关注字段 | 删除非必要字段或提供必要性论证 |
| SDK 清单披露不足 | P1 | 未列 SDK 名称和字段 | 更新 SDK 清单和隐私政策 |
| 第三方责任不清 | P1 | 未提供合同或 DPA | 补充服务商数据处理条款 |

## 5. 整改建议

| 整改项 | 责任方 | 优先级 |
|---|---|---|
| 获取 SDK 官方字段文档和版本号 | 研发 | P1 |
| 抓包核验实际发送字段和域名 | 安全/测试 | P1 |
| 调整 SDK 初始化到同意后 | 研发 | P1 |
| 更新隐私政策、SDK 清单和个人信息清单 | 隐私/产品 | P1 |
| 禁止采集安装列表或提供强必要性论证 | 产品/研发/隐私 | P1 |

## 6. Gate

完成同意链路、字段最小化、SDK 清单和抓包复测前，不建议上架。若无法关闭安装列表采集，应考虑替换 SDK。

## 7. 依据状态

- 待核验依据：App 个人信息保护、SDK 共享和终端权限相关监管规则需核验最新版官方文本。
- 内部规则/风险偏好：高关注字段需隐私和安全双审批。

## 8. 可复制评审结论

【结论】该统计 SDK 当前不建议按启动即初始化方式上线。应先完成 SDK 字段实测、同意后初始化、隐私政策和 SDK 清单更新，并删除或论证安装列表等非必要字段。整改关闭后可灰度上架。
