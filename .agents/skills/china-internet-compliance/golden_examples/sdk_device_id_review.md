# 优秀样例：第三方SDK读取设备标识评审

## 输入摘要
App接入广告归因SDK，SDK会收集设备标识、IP、App列表、启动日志，用于广告投放归因和反作弊。

## 合规评审结论

### 1. 初步结论
- **风险等级**：P1。
- **上线建议**：完成SDK合规评估、隐私政策/SDK清单更新、延迟初始化和用户同意机制后方可上线。

### 2. 主要风险
1. 设备标识、IP、启动日志通常属于个人信息；App列表可能超出归因必要范围。
2. 广告归因和反作弊属于扩展业务目的，不应在用户同意前初始化。
3. SDK作为第三方接收者或委托处理方的法律角色需明确。
4. 若SDK数据出境或由境外主体处理，需触发跨境评估路径判断。

### 3. 审查依据
- 个人信息保护法关于告知、同意、对外提供、委托处理、PIA的要求。
- App治理规则关于SDK清单、权限最小必要、不得未同意启动SDK的监管口径。

### 4. 整改建议
- 删除非必要字段，尤其是App列表。
- SDK延迟初始化至用户同意后。
- 在隐私政策和SDK清单列明SDK名称、公司、目的、字段、共享方式、隐私政策链接。
- 与SDK供应商签署DPA，约定不得超范围处理和再分包。
- 做网络抓包/SDK行为检测并留档。

### 5. 可复制评审结论
广告归因SDK涉及个人信息和第三方共享，且可能存在过度收集设备信息风险。建议按P1处理，完成SDK合规评估、隐私政策更新、延迟初始化、字段最小化和供应商DPA后再上线。
