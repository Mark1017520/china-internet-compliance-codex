# Golden Example — Enterprise RAG Knowledge Base Review

## 1. 输入事实摘要

企业 SaaS 计划为客户提供 RAG 知识库问答。客户可上传合同、客服记录、商品资料和内部制度，系统会切片、向量化并调用第三方大模型生成回答。当前未提供租户隔离设计、向量库权限、模型训练用途、删除机制、敏感信息过滤和输出引用策略。

## 2. 结论前置

- 风险等级：P1 高风险
- 上线建议：完成租户隔离、数据处理协议、模型供应商约束、权限控制、删除机制和输出引用后灰度上线
- 核心理由：企业 RAG 会处理客户商业秘密、合同和可能包含个人信息的客服记录。核心风险不是“能否问答”，而是数据是否被跨租户访问、模型是否再利用、输出是否泄露或编造。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 上传资料 | 合同、客服记录、商品资料、制度 | 高风险 |
| 处理方式 | 切片、向量化、大模型回答 | 高关注 |
| 模型供应商 | 第三方大模型 | 待合同核验 |
| 租户隔离 | 未提供 | 缺失 |
| 删除机制 | 未说明 | 缺失 |
| 输出引用 | 未说明 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 跨租户泄露风险 | P1 | 多客户知识库共用系统 | 逻辑/物理隔离、权限测试和审计 |
| 客户资料再利用风险 | P1 | 第三方模型处理 prompt | DPA 禁止训练和另用 |
| 权限继承不足 | P1 | 文档权限可能复杂 | 按客户原权限做检索授权 |
| 删除不彻底 | P1 | 向量库和缓存可能残留 | 删除原文、切片、向量、缓存和日志 |
| 输出幻觉和泄密 | P1 | 模型生成回答 | 引用来源、置信度、敏感输出拦截 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 完成租户隔离、权限继承和越权测试 | 研发/安全 | 上线前 |
| 与模型/向量库供应商签署 DPA、安全附件和不训练承诺 | 法务/采购 | 上线前 |
| 设计删除链路，覆盖原文、切片、向量、缓存和备份策略 | 研发/安全 | 上线前 |
| 对敏感字段、密钥、个人信息和商业秘密做上传/输出拦截 | 安全/算法 | 上线前 |
| 输出引用来源、置信度和人工复核提示 | 产品/算法 | 灰度前 |

## 6. 上线 Gate

未完成租户隔离测试、供应商 DPA 和删除机制前，不得接入客户生产资料。可使用公开样例文档 PoC。

## 7. 依据状态

- 待核验依据：个人信息保护、数据安全、商业秘密保护、生成式 AI 和供应商处理规则需核验最新版官方文本。
- 内部规则/风险偏好：客户资料进入 RAG 默认按 P1 数据安全和供应商 gate。

## 8. 可复制评审结论

【结论】企业 RAG 知识库应按 P1 审查。上线前需证明租户隔离、权限继承、模型不训练、删除链路、敏感信息拦截和输出引用机制已闭合；否则存在跨租户泄露、客户资料再利用和错误输出风险。
