# 优秀样例：App剪贴板读取功能合规评审

## 输入摘要
移动 App 拟在用户打开商品详情页时自动读取剪贴板，识别外部复制的商品链接并弹出“是否打开相关商品”提示。未说明是否在用户同意前读取、读取频率、是否上传服务器。

## 合规评审结论

### 1. 初步结论
- **风险等级**：P1，高风险但可整改。
- **上线建议**：不得按“静默自动读取并上传”方式上线；可改为用户主动触发或本地识别后再提示。

### 2. 触发场景
- App/终端权限治理。
- 个人信息保护与最小必要。
- 第三方链接识别与日志留存。

### 3. 主要风险
1. 剪贴板可能包含手机号、地址、验证码、订单号等个人信息，静默读取容易被认定为超最小必要。
2. 如读取后上传服务器，需要明确告知处理目的、字段、保存期限和安全措施。
3. 高频读取、后台读取、未使用功能也读取，属于监管通报中的典型高风险形态。

### 4. 法律/规则依据
- 个人信息保护法关于合法、正当、必要、诚信和告知同意义务。
- App治理规则关于权限最小必要、不得频繁/过度索权和不得未同意收集个人信息的要求。

### 5. 整改建议
- 默认不在启动时读取剪贴板。
- 改为用户点击“识别链接”后本地读取。
- 仅识别 URL，不上传剪贴板全文。
- 首次使用前弹窗说明目的、范围、保存期限。
- 不保存原始剪贴板内容；仅保存用户确认打开后的链接识别结果。

### 6. 待确认问题
1. 是否在用户授权前读取？
2. 是否上传服务器？
3. 是否读取剪贴板全文还是只做本地 URL 正则识别？
4. 是否存在第三方 SDK 同步读取？

### 7. 可复制评审结论
该功能涉及剪贴板读取，可能触及个人信息和敏感内容。当前方案如为静默读取或上传服务器，建议按 P1 处理，需改为用户主动触发、本地识别、最小字段处理，并补充弹窗告知和隐私政策说明后再上线。
