# Golden Example — App Clipboard Permission Review

## 1. 输入事实摘要

某电商 App 计划上线“复制口令自动识别优惠券”活动。App 启动时读取剪贴板并上传剪贴板内容到服务端识别口令。产品称可以提升转化率，但未提供用户触发动作、权限说明、剪贴板内容过滤和本地识别方案。

## 2. 结论前置

- 风险等级：P1 高风险
- 上线建议：调整为用户主动触发、本地识别或最小化上传后，方可灰度上线
- 核心理由：启动即读取剪贴板且上传服务端，可能收集与服务无关的个人信息或敏感信息，必要性和最小化不足

## 3. 事实矩阵

| 项目 | 内容 | 状态 |
|---|---|---|
| 权限/能力 | 读取剪贴板 | 已知 |
| 触发时机 | App 启动时 | 高风险 |
| 上传内容 | 剪贴板全文上传服务端 | 高风险 |
| 用户告知 | 未提供弹窗/文案 | 缺失 |
| 替代方案 | 未评估本地识别 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 读取时机过早 | P1 | App 启动即读取 | 改为用户点击“识别口令”后触发 |
| 上传范围过宽 | P1 | 剪贴板全文上传 | 本地正则识别，仅上传命中口令 |
| 告知不足 | P1 | 无显著提示 | 增加目的、范围、触发方式说明 |
| 敏感信息误采风险 | P1 | 剪贴板可能包含验证码、地址、银行卡等 | 增加过滤、丢弃和日志不落盘 |

## 5. 整改建议

1. 删除启动时自动读取逻辑，改为用户主动点击或粘贴。
2. 优先本地识别优惠券口令，不上传剪贴板全文。
3. 只上传命中规则的口令 token，不上传其他文本。
4. 更新隐私政策和个人信息清单，说明剪贴板使用目的。
5. 增加埋点监控：读取次数、命中率、用户关闭率、异常上传拦截。

## 6. Gate

未完成触发时机和上传范围整改前，不建议上线。整改后可小流量灰度，并保留抓包和代码核验证据。

## 7. 依据状态

- 待核验依据：App 个人信息收集、权限调用和必要原则相关规则需核验最新版官方文本。
- 事实假设：剪贴板中可能包含与优惠券无关的个人信息。

## 8. 可复制评审结论

【结论】当前“启动即读取并上传剪贴板全文”的方案不建议上线。建议改为用户主动触发、本地识别、仅上传命中口令，并补充用户告知、隐私政策、抓包复测和代码核验证据后，再按 P1 整改后灰度上线处理。
