# 优秀样例：AGPL后端依赖评审

## 输入摘要
后端服务通过Maven引入AGPL-3.0组件，作为核心业务流程的一部分运行。未修改源码，不向客户分发，服务通过Web向外部用户提供。

## 合规评审结论

### 1. 初步结论
- **风险等级**：P1，需专项确认；若修改AGPL组件或与自研代码强耦合，风险升高。
- **上线建议**：不得仅以“未分发”直接放行；需确认是否修改、链接/集成方式、是否触发网络交互源码义务。

### 2. 主要风险
1. AGPL的网络服务条款对修改版通过网络交互提供服务有特殊要求。
2. Maven依赖通常是进程内集成，需评估是否形成衍生作品或强耦合。
3. 即使未修改，也需保留许可证、版权声明，并核查传递依赖。

### 3. 整改建议
- 确认是否修改、patch、fork或定制构建。
- 做SCA/SBOM并列出传递依赖。
- 评估可否替换为MIT/Apache/BSD组件。
- 如必须使用，隔离为独立服务并仍需确认AGPL影响。
- 准备许可证文本、源码获取路径、修改说明或商业授权方案。

### 4. 可复制评审结论
AGPL Maven依赖用于对外Web服务，不应直接认定低风险。建议按P1处理，完成使用方式、修改情况、网络服务义务、传递依赖和替代方案评估后再上线。
