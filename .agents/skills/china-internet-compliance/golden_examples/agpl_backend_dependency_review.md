# Golden Example — AGPL Backend Dependency Review

## 1. 输入事实摘要

企业 SaaS 后端拟使用 `agpl-report-engine` 生成报表。组件以服务方式部署在后端容器内，未修改源码。公司计划同时提供 SaaS 服务、Docker 镜像交付和部分客户私有化部署。当前没有 SBOM、许可证文本归档、第三方软件清单和客户合同开源条款。

## 2. 结论前置

- 风险等级：P1，高风险；若对外交付镜像或私有化包且无法替换/隔离，可能升级为 P0
- 上线建议：SaaS 场景需进一步核验 AGPL 网络交互义务；镜像和私有化部署在完成替代、隔离或法律复核前不建议交付

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 组件 | `agpl-report-engine` | 待核验版本和许可证文本 |
| 许可证 | AGPL-3.0 | 待核验 |
| 使用方式 | 后端容器服务，生成报表 | 已知 |
| 是否修改源码 | 未修改 | 待代码仓库确认 |
| 对外交付 | SaaS、Docker 镜像、私有化部署 | 已知 |
| 合同披露 | 未提供第三方软件条款 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| AGPL 网络服务义务不明 | P1 | SaaS 后端提供网络访问能力 | 法务核验具体调用方式和许可证文本 |
| 镜像/私有化交付触发分发义务 | P1 | 对客户交付 Docker 镜像和部署包 | 输出第三方软件清单、源码/notice 方案 |
| 客户合同与许可证义务不一致 | P1 | 合同未披露开源限制 | 更新合同附件和第三方软件声明 |
| SBOM 缺失 | P1 | 无完整依赖清单 | 生成 SBOM 并归档许可证 |

## 5. 整改建议

| 整改项 | 责任方 | 优先级 |
|---|---|---|
| 核验组件版本、许可证文本和使用方式 | 研发/法务 | P1 |
| 评估替换为宽松许可证组件或商业授权 | 研发/采购 | P1 |
| 对镜像和私有化部署准备第三方软件清单和 notice | 研发/交付/法务 | P1 |
| 更新客户合同中的第三方软件和开源义务披露 | 法务/销售 | P1 |
| 建立发布前 SBOM/SCA 扫描 gate | 安全/研发 | P2 |

## 6. Gate

SaaS 场景：完成许可证文本核验和架构隔离评估后可灰度。Docker 镜像和私有化部署：在替换、商业授权或法律复核前不建议交付。

## 7. 依据状态

- 待核验依据：AGPL-3.0 义务必须以实际许可证文本、组件版本和调用方式为准。
- 事实假设：该组件作为后端网络服务被用户间接使用。

## 8. 可复制评审结论

【结论】当前 AGPL 后端依赖不建议直接进入 Docker 镜像或私有化交付。应先完成组件版本和许可证文本核验，评估替换、隔离或商业授权方案，并补充 SBOM、notice 和客户合同披露。SaaS 场景也需核验网络服务义务，不应仅因“未修改源码”直接判定低风险。
