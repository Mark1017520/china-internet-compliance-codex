# Golden Example — Cross-Border Model API Review

## 1. 输入事实摘要

产品拟接入境外大模型 API，为中国大陆用户生成客服回复。输入内容可能包含订单号、手机号、收货地址、聊天记录和售后诉求。供应商文档显示服务由境外主体提供，未明确数据处理区域、是否保留日志、是否用于模型训练和子处理者名单。

## 2. 结论前置

- 风险等级：P1 高风险；如传输敏感个人信息、大规模个人信息或重要数据，可能升级为 P0
- 上线建议：不得直接发送原始用户数据至境外模型。需完成数据最小化/脱敏、出境路径判断、模型供应商 DPA、安全评估和用户告知后再灰度
- 核心理由：境外模型 API 同时触发个人信息出境、供应商处理、AI 输出准确性和消费者权益风险。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 接收方 | 境外大模型 API | 高风险 |
| 数据字段 | 订单号、手机号、地址、聊天记录 | 高关注 |
| 训练用途 | 未说明 | 缺失 |
| 部署区域 | 未说明 | 缺失 |
| 脱敏方案 | 未提供 | 缺失 |
| 用户告知 | 未提供 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 出境路径不明 | P1 | 数据发送至境外 API | 完成跨境路径判断和必要文件 |
| 数据最小化不足 | P1 | 原始订单和联系方式进入 prompt | 脱敏、字段白名单和上下文裁剪 |
| 供应商训练用途不清 | P1 | 未承诺不训练 | DPA 明确禁止训练、再利用和长期留存 |
| AI 错误回复风险 | P1 | 生成客服回复影响售后 | 高风险意图转人工，输出需可追溯 |
| 用户告知不足 | P1 | 未披露第三方和 AI 处理 | 更新隐私政策、AI 标识和服务说明 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 建立 prompt 字段白名单，默认脱敏手机号、地址和订单细节 | 研发/安全 | 上线前 |
| 完成数据出境规模和合法路径判断 | 隐私/法务 | 上线前 |
| 签署模型供应商 DPA、安全附件和不训练承诺 | 法务/采购 | 上线前 |
| 设置人工复核、纠错、投诉和回滚机制 | 产品/客服 | 上线前 |
| 更新隐私政策、AI 标识和第三方共享清单 | 产品/隐私 | 上线前 |

## 6. 上线 Gate

未完成脱敏、DPA 和出境路径判断前，不得接入生产用户数据。可使用模拟或脱敏测试数据 PoC。灰度时禁止自动处理退款、赔付、法律承诺等高风险场景。

## 7. 依据状态

- 待核验依据：个人信息保护、数据出境、生成式 AI 服务、供应商处理和消费者权益相关规则需核验最新版官方文本。
- 事实假设：境外模型供应商能够接触 prompt 中的原始用户数据。

## 8. 可复制评审结论

【结论】境外大模型 API 不能直接接收原始客服数据。建议按 P1 处理，先完成字段脱敏、出境路径判断、供应商 DPA/不训练承诺、用户告知和人工兜底。完成前仅允许脱敏 PoC，不得上线生产调用。
