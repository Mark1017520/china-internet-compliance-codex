# Golden Example — Payment Split Review

## 1. 输入事实摘要

平台拟为商家和达人提供自动分账功能。消费者支付后资金先进入平台自有账户，平台按比例结算给商家和达人，并从中扣除服务费。产品材料未提供持牌支付机构方案、资金流图、商户协议、退款/冻结规则、反洗钱/反诈和对账机制。

## 2. 结论前置

- 风险等级：P0/P1
- 上线建议：平台不得自持客户资金后自行分账；应改为持牌支付机构分账/资金存管方案，并完成资金流、合同和风控审查后再评估
- 核心理由：平台自收款再分账可能触发无牌支付、二清、资金池和客户资金安全风险。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 资金路径 | 消费者资金进入平台自有账户 | 阻断 |
| 分账对象 | 商家、达人、平台服务费 | 高风险 |
| 持牌机构 | 未提供 | 缺失 |
| 退款/冻结 | 未说明 | 缺失 |
| 对账 | 未说明 | 缺失 |
| 风控 | 未说明反诈/反洗钱 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 无牌支付/二清风险 | P0 | 平台自有账户收客户资金 | 改为持牌支付机构清分/分账 |
| 资金池风险 | P0/P1 | 平台沉淀客户资金 | 平台不接触备付金或客户资金 |
| 退款和争议不清 | P1 | 多方分账后售后复杂 | 明确退款、冻结、追偿和争议规则 |
| 商户/达人实名和风控不足 | P1 | 分账至多主体 | 完成实名、资质、黑名单和异常交易监控 |
| 合同链不完整 | P1 | 未提供协议 | 更新商户协议、达人协议和支付服务协议 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 接入持牌支付机构分账产品，平台不自持客户资金 | 支付/研发/法务 | 上线前阻断项 |
| 输出资金流、信息流、合同流和发票/税务处理图 | 财务/支付/法务 | 上线前 |
| 完成商家/达人实名、资质、黑名单和异常交易监控 | 风控/运营 | 上线前 |
| 明确退款、冻结、分账失败、争议和追偿规则 | 产品/客服/法务 | 上线前 |
| 签署支付机构协议，明确数据、安全、反诈和责任 | 法务/采购/安全 | 上线前 |

## 6. 上线 Gate

当前“资金先入平台账户再分账”方案应阻断上线。只有切换至持牌支付机构分账路径并完成合同、资金流和风控复核后，方可进入 P1 灰度。

## 7. 依据状态

- 待核验依据：支付结算、非银行支付机构、反洗钱/反诈、电子商务和消费者权益相关规则需核验最新版官方文本。
- 事实假设：平台自身不具备支付清算或资金存管牌照。

## 8. 可复制评审结论

【结论】平台自收消费者资金再向商家和达人分账存在无牌支付、二清和资金池风险，应 P0 阻断当前方案。建议改为持牌支付机构分账产品，并补齐资金流、合同流、退款争议、商户实名和反诈监控后再评估上线。
