# Golden Example — Open Platform Plugin Market Review

## 1. 输入事实摘要

开放平台计划上线第三方插件市场。插件可在商家授权后读取订单、客户手机号、收货地址、店铺装修素材，并可写入优惠券和营销活动。平台当前只设计 OAuth 授权页，未提供插件审核标准、权限分级、数据使用规则、开发者协议、违规下架和数据删除机制。

## 2. 结论前置

- 风险等级：P1 高风险；如允许未审核插件访问客户联系方式或交易数据，可能升级为 P0 阻断
- 上线建议：建立插件准入、权限分级、数据处理协议、商家授权、终端用户告知和审计下架机制后灰度
- 核心理由：第三方插件可接触商家和消费者个人信息，并可写入营销活动，平台需要承担开放生态治理和第三方接入管理责任。

## 3. 事实矩阵

| 事实项 | 已知内容 | 状态 |
|---|---|---|
| 插件能力 | 读取订单/客户信息，写入优惠券/营销活动 | 高风险 |
| 权限授权 | 商家 OAuth 授权页 | 不充分 |
| 开发者审核 | 未提供 | 缺失 |
| 数据处理规则 | 未提供 | 缺失 |
| 违规处置 | 未提供下架/停权/删除 | 缺失 |
| 终端用户告知 | 未说明 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 权限范围过宽 | P1 | 插件可读客户手机号和地址 | 建立 scopes 分级、默认最小权限和敏感权限审批 |
| 第三方责任不清 | P1 | 开发者接收个人信息 | 签署开发者协议、DPA 和安全承诺 |
| 商家授权不足 | P1 | OAuth 页未说明字段和用途 | 授权页逐项展示权限、用途、接收方和撤回方式 |
| 写权限滥用风险 | P1 | 可写优惠券/营销活动 | 写权限需二次确认、审计日志和风控拦截 |
| 违规处置缺失 | P1 | 无下架和删除机制 | 建立停权、下架、数据删除和商家通知流程 |

## 5. 证据缺口

- 插件权限 scopes 设计和敏感权限审批标准
- 开发者协议、API 条款、DPA、安全标准和隐私政策要求
- 插件审核清单、测试账号、渗透/安全检查要求
- 商家授权页和撤销授权路径截图
- 日志留存、异常调用告警、数据删除证明和违规处置 SOP

## 6. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 将客户手机号、地址、订单详情列为敏感 scopes，默认关闭 | 平台产品/研发 | 上线前 |
| 建立插件准入审核、最小权限、回调域名和数据安全检查 | 平台治理/安全 | 上线前 |
| 更新开发者协议、API 条款和数据处理附件 | 法务/平台治理 | 上线前 |
| OAuth 页展示权限、用途、开发者主体、隐私政策和撤回方式 | 产品/前端 | 上线前 |
| 建立异常调用告警、停权、下架、商家通知和数据删除证明 | 安全/运营 | 灰度前 |

## 7. 上线 Gate

未完成权限分级、开发者协议、商家授权页和违规处置机制前，不建议开放生产数据 API。可先以沙箱环境和低敏 scopes 灰度，禁止第三方插件直接读取客户手机号和收货地址。

## 8. 依据状态

- 待核验依据：个人信息委托/共享、平台治理、网络安全和 API 数据安全相关规则需核验最新版官方文本。
- 内部规则/风险偏好：开放平台敏感 scopes 应纳入安全、隐私和法务三方审批。

## 9. 可复制评审结论

【结论】第三方插件市场不能只依赖商家 OAuth 授权上线。该项目应按 P1 处理，先完成权限分级、开发者准入、DPA/API 条款、商家授权告知、日志审计、违规下架和数据删除机制。敏感客户信息 scopes 在机制闭合前不得开放给第三方插件。
