# Golden Example — SSPL Database Service Review

## 1. 输入事实摘要

研发计划使用 SSPL 许可证数据库作为生产业务数据库，存储用户订单和日志。公司不修改源码，但未来可能提供私有化部署包和托管数据分析服务。当前未提供版本号、许可证文本、发行渠道、商业授权、替代方案和客户交付形态说明。

## 2. 结论前置

- 风险等级：P1 高风险；若作为托管数据库服务或私有化交付且无法满足许可证义务，可能升级为 P0
- 上线建议：优先采购商业授权、使用云厂商合规版本或替换为宽松许可证数据库；未完成许可证专项复核前，不建议作为核心生产依赖
- 核心理由：SSPL 对“作为服务提供”的义务边界较强，不能因“未修改源码”直接判定低风险。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| 组件 | SSPL 数据库 | 高风险许可证 |
| 使用方式 | 生产业务数据库 | 高关注 |
| 是否修改 | 不修改源码 | 待核验 |
| 未来交付 | 私有化部署、托管分析服务可能涉及 | 高风险 |
| 商业授权 | 未提供 | 缺失 |
| 替代方案 | 未评估 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 服务化义务边界不明 | P1 | 可能提供托管分析服务 | 法务核验许可证和业务形态 |
| 私有化交付风险 | P1/P0 | 可能随部署包交付 | 明确是否分发、是否需开放相关代码 |
| 版本和来源不清 | P1 | 未提供版本和发行渠道 | 固定版本、许可证文本和下载来源 |
| 客户合同缺口 | P1 | 未披露第三方软件 | 更新第三方软件清单和开源条款 |
| 数据安全风险 | P2 | 存储订单和日志 | 完成访问、备份、加密和运维评估 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 核验版本、许可证文本、发行渠道和使用边界 | 研发/法务 | 上线前 |
| 优先采购商业授权或替换为宽松许可证组件 | 研发/采购 | 上线前 |
| 明确 SaaS、托管服务、Docker 镜像和私有化交付义务差异 | 法务/交付 | 上线前 |
| 更新 SBOM、第三方软件清单、notice 和客户合同附件 | 研发/法务 | 上线前 |
| 完成数据库安全、备份、访问控制和供应商支持评估 | 安全/运维 | 灰度前 |

## 6. 上线 Gate

未完成许可证文本核验和业务形态判断前，不建议作为核心生产数据库上线。私有化部署和托管数据库服务应单独 gate，不能沿用普通 SaaS 内部使用结论。

## 7. 依据状态

- 待核验依据：SSPL 许可证文本、组件版本、客户合同和开源合规政策需逐项核验。
- 内部规则/风险偏好：SSPL 默认纳入高风险许可证清单。

## 8. 可复制评审结论

【结论】SSPL 数据库不宜按普通开源组件处理。建议按 P1 进行许可证专项评估，优先选择商业授权、云厂商合规版本或替代数据库，并补齐 SBOM、第三方软件清单和客户合同披露；涉及私有化或托管服务时应重新评估是否阻断。
