# Golden Example — Enterprise API Vendor Review

## 1. 输入事实摘要

公司计划向企业客户开放 API，允许客户系统批量拉取订单、会员、优惠券和售后数据。API 也将由第三方实施服务商代客户调用。当前只设计 API key，无 OAuth scopes、IP 白名单、调用频控、审计日志、客户授权证明和服务商 DPA。

## 2. 结论前置

- 风险等级：P1 高风险
- 上线建议：补齐客户授权、最小权限 scopes、服务商约束、安全控制和审计留痕后再开放生产 API
- 核心理由：企业 API 会批量输出交易和会员个人信息，且可能由第三方服务商代调用。API key 单点凭证不足以证明授权边界和安全可控。

## 3. 事实矩阵

| 事实项 | 内容 | 状态 |
|---|---|---|
| API 数据 | 订单、会员、优惠券、售后 | 高风险 |
| 调用方 | 企业客户和第三方服务商 | 高关注 |
| 鉴权 | API key | 不充分 |
| 权限分级 | 未设计 | 缺失 |
| 日志审计 | 未说明 | 缺失 |
| DPA | 未提供 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 授权边界不足 | P1 | 客户和服务商均可调用 | 客户明确授权、服务商代调用证明 |
| 权限过宽 | P1 | 批量拉取多类数据 | OAuth scopes、字段级权限和有效期 |
| 安全控制不足 | P1 | 仅 API key | IP 白名单、密钥轮换、频控和异常告警 |
| 审计留痕不足 | P1 | 批量数据输出 | 完整调用日志、导出记录和客户可见审计 |
| 第三方责任不清 | P1 | 实施服务商代调用 | 签署 DPA、保密、安全和删除义务 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 设计 scopes、字段级权限、有效期和撤销机制 | 平台产品/研发 | 上线前 |
| 建立客户授权页和第三方服务商代调用确认流程 | 产品/法务 | 上线前 |
| 增加 IP 白名单、频控、密钥轮换、异常调用告警 | 安全/研发 | 上线前 |
| 输出 API 条款、DPA 和开发者安全规范 | 法务/平台治理 | 上线前 |
| 建立日志留存、客户审计下载和违规停权机制 | 安全/运营 | 灰度前 |

## 6. 上线 Gate

未完成 scopes、客户授权和服务商 DPA 前，不建议开放生产数据 API。可先在沙箱环境开放非敏感测试数据。

## 7. 依据状态

- 待核验依据：个人信息共享/委托、网络安全、API 数据安全和企业客户合同相关规则需核验最新版官方文本。
- 内部规则/风险偏好：批量数据 API 默认纳入安全和法务双 gate。

## 8. 可复制评审结论

【结论】企业 API 不应仅凭 API key 开放订单和会员数据。建议按 P1 处理，补齐客户授权、最小权限 scopes、第三方服务商 DPA、安全控制、审计日志和违规停权机制后，再开放生产调用。
