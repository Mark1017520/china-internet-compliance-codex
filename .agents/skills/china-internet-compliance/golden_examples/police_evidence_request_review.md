# Golden Example — Police Evidence Request Review

## 1. 输入事实摘要

公安机关通过盖章协查函要求平台提供某账号在 2026-05-01 至 2026-05-07 的登录 IP、订单金额和操作日志。业务团队拟同时提供该账号全量历史日志、源代码片段和内部风控标签。

## 2. 结论前置

- 风险等级：P1 高风险
- 响应建议：补齐文书核验和内部审批后，按函件限定账号、时间段和字段最小必要提供
- 阻断事项：全量历史日志、源代码片段和内部风控标签超出当前文书范围，原则上不提供

## 3. 事实矩阵

| 项目 | 内容 | 状态 |
|---|---|---|
| 请求主体 | 公安机关，盖章协查函 | 待核验联系人和送达方式 |
| 请求范围 | 特定账号、7 天、登录 IP/订单金额/操作日志 | 已初步明确 |
| 拟提供材料 | 全量日志、源代码、风控标签 | 存在超范围 |
| 涉及数据 | 个人信息、订单信息、操作日志、商业秘密 | 高敏材料 |
| 内部审批 | 未提供 | 缺失 |

## 4. 主要法律/规则问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 文书真实性和范围需核验 | P1 | 仅有扫描件，未说明联系人和送达链路 | 法务核验原件/盖章/联系人/案号 |
| 超范围提供个人信息 | P1 | 拟提供全量历史日志 | 限定账号、字段、时间段 |
| 泄露商业秘密和安全机制 | P1 | 拟提供源代码和风控标签 | 改为字段解释或技术说明 |
| 证据链留痕不足 | P1 | 未提供查询、导出、复核记录 | 建立审批、导出、交付和签收记录 |

## 5. 响应方案

| 材料 | 处理建议 | 理由 |
|---|---|---|
| 登录 IP | 可提供 | 在函件范围内 |
| 订单金额 | 可提供 | 在函件范围内，注意订单号和金额字段限定 |
| 操作日志 | 可提供限定字段 | 仅限账号、时间段、必要操作 |
| 全量历史日志 | 不提供 | 超范围且包含无关个人信息 |
| 源代码片段 | 原则不提供 | 涉及商业秘密和安全机制 |
| 内部风控标签 | 原则不提供 | 超范围且可能泄露风控策略 |

## 6. 内部流程

1. 法务核验函件主体、案号、盖章、联系人和送达方式。
2. 安全/数据团队按字段和时间段导出。
3. 双人复核导出结果，生成材料目录和 hash 或签收记录。
4. 对外回复说明提供范围；对超范围材料说明无法按当前函件提供。
5. 保存原始文书、审批记录、查询日志、导出文件、交付记录。

## 7. Gate

未完成文书核验和内部审批前，不得导出或交付数据。不得删除、篡改、补造或隐藏日志。

## 8. 依据状态

- 待核验依据：公安调证、个人信息提供、证据响应和日志留存相关规则需核验最新版官方文本及公司制度。
- 内部规则/风险偏好：源代码、风控标签、商业秘密原则上需管理层和法务双审批。

## 9. 可复制评审结论

【结论】可在核验函件真实性和完成内部审批后，按函件限定账号、时间段和字段最小必要提供登录 IP、订单金额及必要操作日志。当前拟提供全量日志、源代码和内部风控标签存在超范围提供个人信息、泄露商业秘密和破坏证据边界风险，应剔除或改为字段说明。
