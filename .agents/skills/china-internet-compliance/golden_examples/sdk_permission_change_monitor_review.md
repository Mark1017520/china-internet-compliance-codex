# Golden Example — SDK Permission Change Monitor Review

## 1. 输入事实摘要

App 新版本升级第三方统计 SDK 后，权限清单新增剪贴板读取、精确定位和后台定位能力。SDK Release Notes 仅说明“提升归因准确率”，未解释字段必要性。产品计划随版本直接上架，隐私政策和 SDK 清单未更新，也未进行抓包复测。

## 2. 结论前置

- 风险等级：P1 高风险
- 上线建议：阻断当前版本上架，待权限移除或完成必要性论证、同意链路、隐私披露和抓包复测后再发布
- 核心理由：统计 SDK 新增剪贴板和精确定位属于高关注权限，且与“统计分析”目的之间的必要性不足。未经验证直接发布可能构成超范围收集和同意前调用。

## 3. 事实矩阵

| 事实项 | 已知内容 | 状态 |
|---|---|---|
| SDK 变化 | 新增剪贴板、精确定位、后台定位 | 高风险 |
| 变更理由 | 提升归因准确率 | 不充分 |
| 初始化时机 | 未说明，可能启动即初始化 | 待实测 |
| 隐私政策 | 未更新 | 缺失 |
| 抓包复测 | 未进行 | 缺失 |
| 替代方案 | 未评估 | 缺失 |

## 4. 主要问题

| 问题 | 等级 | 触发事实 | 关闭标准 |
|---|---|---|---|
| 权限必要性不足 | P1 | 统计 SDK 读取剪贴板和精确定位 | 删除权限或形成强必要性论证 |
| 同意链路不明 | P1 | 可能启动即初始化 | 用户同意前不得采集或上传 |
| 隐私披露缺失 | P1 | SDK 清单未更新 | 披露 SDK 名称、字段、目的、接收方 |
| 实际采集不可控 | P1 | 未抓包复测 | 出具域名、字段、频率和触发条件测试报告 |
| 供应商约束不足 | P2 | Release Notes 解释笼统 | 更新 DPA/安全附件和字段变更通知义务 |

## 5. 整改建议与责任方

| 整改项 | 责任方 | Gate |
|---|---|---|
| 暂停该版本上架或回退 SDK 版本 | 发布负责人/研发 | 立即 |
| 要求 SDK 供应商提供字段和权限必要性说明 | 采购/研发/隐私 | 上线前 |
| 删除剪贴板、后台定位等非必要权限或改为用户主动触发 | 研发 | 上线前 |
| 更新隐私政策、SDK 清单、权限弹窗和应用市场材料 | 隐私/产品 | 上线前 |
| 完成抓包复测和代码核验，归档证据 | 安全/测试 | 上线前 |

## 6. 上线 Gate

当前版本应阻断上架。仅在删除高风险权限，或完成强必要性论证、同意链路、披露更新和抓包复测后，方可灰度发布。若 SDK 无法关闭相关权限，应替换供应商。

## 7. 依据状态

- 待核验依据：App 个人信息保护、SDK 权限调用、移动应用合规检测相关规则需核验最新版官方文本。
- 事实假设：新增权限由第三方 SDK 自动申请或调用。

## 8. 可复制评审结论

【结论】SDK 升级新增剪贴板和精确定位权限，不能按普通依赖升级处理。建议按 P1 阻断当前版本上架，先完成权限移除或必要性论证、同意链路、隐私披露、供应商约束和抓包复测；否则存在超范围收集和应用市场审核风险。
